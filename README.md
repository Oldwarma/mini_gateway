# 智能体迷你网关 (Agent Mini Gateway)

基于**可追踪 Harness 架构**的智能体网关。

## 核心思想

$$
\text{Agent} = \text{LLM} + \text{Harness}
$$

Harness 不是一门技术，也不是一个框架，而是一种智能体的开发架构方案。其设计核心是：

> **把 LLM 压缩到最小范围，用代码包围它。**

AI 发展的三个阶段：

| 阶段 | 解决的问题 | 典型工作 |
| ---- | ---------- | -------- |
| **Prompt Engineering** | 怎么把指令说清楚，模型理解减少歧义 | 系统提示词设计、Few-shot示例、思维链引导 |
| **Context Engineering** | 在合适时机给模型提供正确且必要的信息 | 上下文管理、RAG、记忆注入、Token优化 |
| **Harness Engineering** | 构建一个稳定可靠的系统（执行、纠偏、观测和恢复） | 文件系统、沙箱、约束执行、反馈回路、观测 |

## 架构要点

传统智能体中 LLM 是大脑，包揽所有决策（感知、推理、执行、观察、再感知），一旦 LLM 出错，后续所有节点都会跟着错。

Harness 架构把决策拆开，用**确定性的代码**拥有控制层，LLM 只负责「措辞」这一个环节：

```
用户输入 → 代码: 实体路由 → 代码: 筛选声明 → 代码: 规划结构 → LLM: 措辞 → 代码: 验证 → 输出
```

答案在输出给用户之前，必须同时通过**七维检查**（来源锚定、实体路由、追踪完整性、输出清洁、接口行为、延迟、组合边界行为），任何一道不通过就不能输出——失败时回退到确定性模板引擎，再失败则标记异常进入人工复核/熔断降级。
