# ADR-0002: 实体路由由代码规则驱动（非 LLM）

- 状态: 提议
- 日期: 2026-08-18
- 决策者: joema
- 涉及 spec: 无（架构层，SPEC-002 实体路由落地时引用）
- 关联 ADR: [ADR-0001](ADR-0001-tech-stack.md)

## 背景 / 上下文

论文强调：传统智能体把感知/推理/执行都交给 LLM，一旦 LLM 感知出错，后续所有节点跟着错（贡献四）。实体路由（确定问题指向哪个实体）是感知的关键环节，应交给确定性代码。

## 决策

v1 实体路由用**代码规则 + 正则匹配**，不调用 LLM：

- 实体表（`entities`）注册名称与别名；
- 路由规则：名称/别名精确与模糊匹配、正则模式；
- 匹配失败 → 返回"无法路由"，进入兜底处理（而非猜一个）。

## 后果

**正面：**
- 确定性、可单测、可审计（匹配命中了哪条规则可追溯）
- 零 LLM 成本、零延迟波动
- 符合 Harness 理念：感知环节由代码拥有

**负面：**
- 需要人工维护规则与别名
- 复杂指代（"他们"、"该公司"、同义词扩展）解析能力弱 → 留作 v2（轻量 NER）

## 替代方案

- **LLM 判断实体归属** —— 否决：LLM 判断不可追踪、出错会级联，正是 Harness 要解决的问题。
- **只做精确匹配** —— 部分采纳：先精确，再正则模糊，分两层。
