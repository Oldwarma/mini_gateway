# ADR-0003: 组合边界（LLM 只管措辞 + 确定性模板回退）

- 状态: 提议
- 日期: 2026-08-18
- 决策者: joema
- 涉及 spec: 无（架构层）
- 关联 ADR: [ADR-0001](ADR-0001-tech-stack.md) · [ADR-0004](ADR-0004-validation-gate.md)

## 背景 / 上下文

论文贡献三：一个**可替换的组合边界**，把确定性 Harness 控制与 LLM 措辞分离。传统架构里 LLM 承担理解/判断/组织/措辞/安全全部职责；Harness 架构中这些由代码承担，LLM 只在最后"措辞"。

## 决策

组合边界（`compose/boundary.py`）支持两条路径：

1. **LLM 措辞路径**：把选中的声明 + AnswerContract 合约交给 LLM，生成自然语言答案（只做措辞，不做判断）。
2. **确定性模板路径**：把声明填入模板，直接产出答案（不调用 LLM），作为回退。

选择逻辑：默认走 LLM；LLM 不可用 / 无 API key / 超时 / 验证失败时回退模板路径。模板路径答案再经验证门；仍失败则标记异常/熔断。

## 后果

**正面：**
- LLM 只负责措辞，答案结构受合约约束，判断与选择由代码完成
- 无 LLM key 也能运行整个闭环（模板路径），便于先验证 Harness
- 模型可替换（adapter），可随时切换 provider

**负面：**
- LLM 措辞可能引入润色性偏差 → 由验证门④（输出清洁）兜底
- 模板路径答案生硬、缺乏自然语言组织

## 替代方案

- **LLM 全权输出（传统架构）** —— 否决：LLM 出错导致全链路错，正是 Harness 要解决的。
- **纯模板（永不调 LLM）** —— 否决：损失自然语言表达质量；LLM 措辞是组合边界的重要价值。
