# ADR-0004: 七维验证门（答案输出前必须全部通过）

- 状态: 提议
- 日期: 2026-08-18
- 决策者: joema
- 涉及 spec: 无（架构层）
- 关联 ADR: [ADR-0003](ADR-0003-composition-boundary.md)

## 背景 / 上下文

论文贡献四：一套系统级验证设计——**答案输出给用户之前，必须同时通过七道检查，任何一道不通过就不能输出**。检查来源锚定、实体路由、追踪完整性、输出清洁、运行时接口行为、延迟、组合边界行为。

## 决策

v1 实现七维验证门（`validate/gate.py`），并行执行：

① 来源锚定 → 每个声明有 source_ref + page
② 实体路由 → 声明归属与路由结果一致
③ 追踪完整性 → trace 全链路记录存在
④ 输出清洁 → 格式 / 敏感词 / 幻觉性断言过滤
⑤ 接口行为 → 组合边界路径选择符合预期
⑥ 延迟 → 响应在预算内（config 可配，默认 5s）
⑦ 组合边界行为 → 多声明组合无事实冲突

失败处理：任一不通过 → 回退模板路径 → 重新验证 → 仍失败 → 标记异常 / 熔断。

## 后果

**正面：**
- 答案可信、可审计；任何答案都能说清"为什么通过/为什么失败"
- 验证结果本身写入 trace，构成审计证据

**负面：**
- 实现成本高于直接输出
- ③⑤⑦ 在 v1 为简化实现（全链路 trace、路径记录、基础冲突检查），粒度留作演进

## 替代方案

- **无验证门，直接输出** —— 否决：无法保证质量与可追溯性，违背项目核心理念。
